## 3. 原始计算及主要瓶颈

二维 valid convolution 为：

```text
output[j, i] = Σjk Σik input[j + jk, i + ik] × kernel[jk, ik]
```

输出尺寸为：

```text
outputHeight = inputHeight - kernelHeight + 1
outputWidth  = inputWidth  - kernelWidth  + 1
```

初版为 `j → i → jk → ik` 四重循环。它一次只更新一个输出，最内层反复读写同一输出元素，存在很长的浮点累加依赖链，地址计算较多，也难以利用 512 位 SVE 和 SME 矩阵外积单元。

## 4. 当前 SME 算法

### 4.1 把相邻输出行改写成外积

当前微内核同时计算 16 个相邻输出行和 64 个相邻输出列。对于某个物理输入行和卷积核列：

- 一个 16-lane 向量保存 16 个输出行各自对应的卷积核系数；
- 一个 16-lane 向量保存 16 个相邻输出列的输入值；
- 一条 SME `FMOPA` 将两个向量做外积并累加到一个 16×16 ZA tile；
- 同时使用 4 个 ZA tile，覆盖 16×64 输出块。

这正好把原本大量标量乘加映射到鲲鹏 CPU 的 SME 矩阵流水线。每个输出元素内部仍按物理行和卷积核列的确定次序累加，官方四项实测最大误差为 0。

### 4.2 卷积核打包

调用开始时将卷积核打包为适合 SME 的连续向量：

```text
packed[physicalRow][kernelCol][outputRowLane]
```

无效的顶部和底部行 lane 填 0。打包缓冲区按 64 字节边界对齐，每次调用重新生成并在结束时释放，不跨调用缓存结果。其大小天然为 64 字节整数倍。两轮交错 A/B 中，对齐使四项总分稳定提升约 2.65%；公开最大卷积核下缓冲区约为数百 KiB，能够明显改善连续加载和地址生成。

### 4.3 SVE 滑动窗口复用

卷积核列每 16 列为一组。每组从 5 个连续输入向量开始，通过 15 次逐 lane 滚动的 SVE `EXT` 生成右移窗口，供 4 个 ZA tile 复用。与直接为每个偏移生成 `EXT(input0,input1,shift)` 相比，滚动形式把热循环中的向量 `MOV` 静态计数从 77 条降到 22 条；相邻 16 列组还继续携带 4 个窗口，只加载一个新的末端向量。该变化保持每个输出元素的累加顺序，四个官方 Case 最大误差仍为 0。

### 4.4 缓存和写回

- 在最后若干物理输入行中分批预取即将写回的输出缓存行；
- 对 41–64 宽的中等卷积核每步预取两行，其他宽度每步预取一行；
- 39/41/55 宽卷积核把每个行块拆成 4 个列任务，较宽卷积核拆成 2 个列任务，在负载均衡和顺序缓存局部性间折中；
- 完整 64 列块直接从 4 个 ZA tile 写回，宽度尾部使用谓词化 SME 路径。

这些选择基于宽度区间和通用工作量，不是对四组完整公开尺寸进行硬编码。

### 4.5 兼容回退

如果编译器或 CPU 没有 SME，代码仍保留显式 SVE 路径；若连 SVE 也不可用，则回退到通用 OpenMP/SIMD 实现。GCC 12 当前不提供本实现使用的 SME ACLE，因此 `run.sh` 的 GCC 模式会显式关闭 SME；正式性能路线默认使用 BiSheng。

## 10. 后续最有价值的优化方向

1. 使用独立诊断 harness 隔离 `conv2d` 的性能计数器；直接统计官方程序会被慢速参考卷积淹没；
2. 导出最终 SME 热循环汇编，检查 `FMOPA` 间隔、SVE spill、寄存器分配和加载调度；
3. 尝试手写双 kernel 寄存器软件流水，在不超过误差阈值的前提下交错加载、`EXT` 和 `FMOPA`；
4. 研究保持 SME 外积密度的跨 row-tile 边缘合并；已证明逐行 SVE 边缘不可行；
5. 在完成 64 字节对齐后，继续扫描 packed physical-row padding、L1 组冲突和输出预取距离；
6. 定位 Case 2 的 L1/L2/TLB 或线程长尾问题；
7. 在 NUMA 5、7 等低负载节点重复 A/B，而不是依据实时榜单或单次峰值判断。

任何后续方案仍必须遵守：正确性 PASS、泛化、单 NUMA、最多 38 核、不得修改测试程序，以及单 Case 不超过 18000 GFLOPS。

## 12. 2026-08-28 08:30–11:55 CST 调参、访存与算法实验补充

本轮新增了通用编译期调参宏，用于搜索小/大 kernel 的列任务数、kernel 宽度分界、三档输出预取行数和尾循环展开因子。宏只按通用的 kernel 范围生成代码，没有加入四个公开完整尺寸的判断；所有候选还使用非公开尺寸做泛化复验。

主要结论如下：

- packed 行 padding 对 Case 4 退化约 5.6%–27%，淘汰；
- Case 2 使用 5 个列任务时三轮均值约快 1.32%，但 Case 1/3 约慢 2%，额外 45×45 尺寸也约慢 0.7%，判定为过拟合，默认仍为 4；
- kernel 尾循环展开 2 只在 Case 2 单轮约快 1.25%，其余 Case 和额外尺寸回退，默认仍为 1；
- 64 字节循环对齐只改善 Case 2，却使 Case 4 约慢 1.98%，继续使用 32；
- LTO 四项总差约 +0.06%，属于噪声；
- 两种输入滑窗尾部复用均因 `EXT` 依赖链和寄存器压力退化；合并 ZA 输出尾部使 Case 3/4 约慢 4%–6%，相关失败代码已删除；
- 独立诊断中 Case 1/4 的 L1D miss 约 2.02%/2.20%，dTLB miss 约 0.57%/0.85%，IPC 约 1.68/1.32。大 kernel 更受 load/TLB/地址生成影响，但尚无证据断言已经达到 DRAM 带宽墙；
- 热循环汇编没有观察到 SVE 栈 spill，说明手写 SME 汇编更可能是低个位数调度收益，不能单独把总占比推到 90%。

本轮最终 NUMA 7、38 线程、每 Case 重复 3 次的结果为 `11764.3089 / 10494.5821 / 13137.1432 / 12347.9340 GFLOPS`，合计 `47743.9682 GFLOPS`，为理论总上限的 `66.31%`，四项 PASS、最大误差 0。共享机器相邻运行的同一 Case 可波动十余个百分点，因此没有用峰值宣称新的稳定提升；既有稳定五轮均值 `48612.1378 GFLOPS（67.52%）` 仍作为阶段基准。

完整实验表、失败原因、替代算法判断和下一轮路线见长报告第 12 节。下一阶段优先级为：补齐 L2/带宽/stall/每线程计数器；设计跨 row-tile 的 SME 边缘合并以减少 `kernelHeight+15` 额外外积；评估不生成完整 im2col 的小块 implicit GEMM；最后才在证据支持下实现受控 SME 汇编微内核。FFT 仅作为独立精度原型，必须先证明随机数据全部满足绝对误差 `1e-5` 并确认规则允许。

## 11. 结构工作量模型的修正

当前 16 行 SME 对角映射每个 row tile 要执行 `kernelHeight + 15` 个物理行，而计分只统计 `kernelHeight` 个有效行。它只能描述有效 lane 比例和工作膨胀，不能作为绝对结构上限：

| Case | kernelHeight | 有效 lane 比例 | 相对有效工作膨胀 |
|---|---:|---:|---:|
| Case 1 | 39 | 72.22% | 1.3846× |
| Case 2 | 41 | 73.21% | 1.3659× |
| Case 3 | 55 | 78.57% | 1.2727× |
| Case 4 | 81 | 84.38% | 1.1852× |

必须修正此前推断：官方 `18000` 是赛事政策上限，不是已经测得的原始 `FMOPA` 峰值，因此不能据此断言当前结构最多约 77%，也不能把“去掉 +15 后约 87.42%”当作可达预测。

对相邻 32 个输出行重新计数后，逐全局输入行所需的最少 `FMOPA` 数仍为 `2×(kernelHeight+15)`，与两个 16 行 tile 分开计算相同；32×32 双行块原型也使 Case 2 退化约 18.6%。因此简单跨 tile 拼边不能消除这部分工作。80%/90% 仍分别需要约 18.5%/33.3% 的整体相对提升，必须由新的实际 A/B 证据支持。

FFT、implicit GEMM 等数学替代路线只有在随机数据误差稳定不超过 `1e-5`、不超过单项 18000、且获得官方规则允许时才值得进入性能实现。详细推导、各缓存/数学/核心/指令方向和实验退出条件见长报告第 7–8、16 节。

## 19. 2026-08-31 15:25–16:20 CST 理论上限与新架构复核

按服务器实测 2.0 GHz、38 核和手册 FP32 SME `256 FLOP/cycle/core` 计算，原始峰值约 `19456 GFLOPS`。官方 `18000` 很可能对应 37 个计算核、约 1.9 GHz（`17996.8`），但官方未公布公式，因此只作为推测。
